## Data locations (cluster)
- Real-space fields: `/local00/bioinf/galletti/preprocessed_kvikio/iteration_{N}_ifft_realpotens/` — `data/timestep_{ts:05d}.bin` fp32 `(2,32,8,16,85,32)` = (re/im, vpar, mu, s, x, y) + `metadata.pkl` (geometry, params, flux). y is a COMPLEX analytic signal (one-sided ky storage), so both re/im channels are nonzero.
- Raw spectral K-files: `/restricteddata/ukaea/gyrokinetics/raw/iteration_{N}/` — float64 Fortran-order `(2,32,8,16,85,32)` = (re/im, vpar, mu, s, kx, ky); list via `K_files()` convention (K01..K99 + digit files; ts index maps 1:1). **kx is stored ZERO-CENTERED (zero mode idx 42); ky is ONE-SIDED ky=0..31** (krho monotone, parseval=[1,32,…,32]). `fastops.K_to_real` == `preprocess.do_ifft`, BIT-EXACT vs the local00 bins.
- Linear runs (conditioning): `/restricteddata/ukaea/gyrokinetics/raw/iteration_{N}_Lin/FDS` — ONE eigenmode snapshot per trajectory, same float64 Fortran-order `(2,32,8,16,85,32)` K-file layout (kx zero-centered, ky one-sided); rebuttal `extra_*` runs keep theirs in `_Lin_gkw`, `ood_*` under `raw/ood/`. Amplitude is arbitrary — RMS-normalize. Record the pairing in the trajectory metadata with `python -m neugk_jax.dataset.preprocess --mode=linear` (adds `linear_fds`, and with `--materialize` a transformed `data/linear.bin` + `linear_bin`/`linear_shape`; edits full + light pickles atomically, works on an already-processed dataset).
- CGYRO: `/restricteddata/ukaea/gyrokinetics/raw/cgyro_input_*/` — `bin.cgyro.restart*` = 16 KiB header + 2^26 complex128, C-reshape `(ky64, sp2, E8, xi32, kx64, th32)` (theta fastest; verified from energy profiles: ky/kx spectral-decaying, E smooth, theta smoothest).

## gyrowave compression (neugk_jax/gyrowave/compress/)
Frame = **full 5-axis DWT (default, production)**: sym4, level 3, periodization, on (v,mu,s,x,y) for real bins or (v,mu,s,kx,ky) for K-files — the SAME transform for both (wavelets run directly over the Fourier coefficients; lossless at full support, ~160 dB fp32 round-trip). Field is linear in coefficients ⇒ heat flux is an exact quadratic form `Q=cᵀMc`; per-snapshot support = top-|c| (+ optional flux-importance), then phi-aware CG + flux Gauss-Newton refit. **HL velocity-moments basis is EXPERIMENTAL** (old fidelity bottleneck). **Resolution invariance: production DWT is grid-tied (matched coeffs of identical content differ ~1.0 across grids — cannot be normalized away). Route = canonical physical-basis projection (`gyrowave/compress_exp/canonical.py`, DWT+quadrature only, no FFT): converges at resolved scales (approx 3.7e-3 @2x synthetic, 2.4e-2 @2x on real v-axis; broadband spatial axes only above the coarse Nyquist). Report: `/local00/bioinf/galletti/gyrowave_dwt_wip/WP0_RESOLUTION_REPORT.md`.**

Key env vars (set BEFORE import; `pipeline` captures `CSHAPE`/`M_TOT` at import):
`GYROWAVE_BASIS=dwt|hl` (default dwt), `GYROWAVE_WAVELET=sym4` (scan: sym4 ≈ coif1 > db4 > db2 > haar), `GYROWAVE_H/L` (hl only).

Run compression:
```bash
P=/system/apps/userenv/galletti/mhd/bin/python
$P -m neugk_jax.gyrowave.compress.process_trajectory --version real --traj iteration_13 \
  --support per_snapshot --alpha 1 --beta 0 --gamma 0 --cr 400 --out tokens.npz \
  --full-out full.npz        # optional chained LOSSLESS dump (same fwd pass)
```
- `--version real|semispectral`: local00 bins vs raw K-files (same driver, same frame, same scoring on the real field).
- `--support per_snapshot|shared|full`: physics/amplitude support per snapshot, one shared support, or lossless full dump (prune later). `full` writes `(S,M_TOT)` tok_re/im with `coords_implicit=True`.
- Support selection weights `(alpha df, beta phi, gamma flux)`; for dwt the beta term is skipped (phi_atom_energy is HL-only; top-|c| verified equivalent after flux-GN).
- Verified (iteration_13, dwt sym4): lossless 159–160 dB both versions; CR400 sparse fit: real df 34.6–35.8 / phi ~26 / flux ~3.3–3.6%, K df 35.7–36.9 (spectral side ≈ +1 dB). CGYRO restart (full DWT all 6 axes, complex128→complex64): lossless 170 dB, CR400 top-|c| 42.3 dB.
- `sweep.py <traj_json> <out_dir> [versions] [shard n]`: multi-trajectory driver, resumable, shardable.

## Dataset / training side
- Wavelet-compressed datasets use the kvikio-like layout `<root>/iteration_{it}_dwt/{metadata.npz, data.npz}`: **data.npz = position–amplitude pairs only** (offsets, coords, re/im, timesteps=dump indices, cshape, res); **metadata.npz** (backend `save_meta` format, written AT COMPRESS TIME by `process_trajectory`) = legacy-style metadata: full timesteps/flux series, params (ion_temp_grad/density_grad/s_hat/q), ds, geometry, kyspec/fluxspec, coeff stats (`val_re/val_im_{mean,var,std,min,max,median,kurtosis,skew}`), information-loss stats (`fid_{df_psnr,phi_psnr,flux_relerr,zonal_phi_ratio}[_mean,_std]`, lam_eff), ntok, config echo.
- `dataset/backend.py` `WaveletBackend`: `format_path` appends `_dwt` (like kvikio `_ifft_realpotens`), `read_metadata`, `read_data` — handles: sparse caches (tok_offsets/tok_coord), VARIABLE-LENGTH supports (raw-zero padding + validity mask), and DENSE full dumps (`coords_implicit=True`): dense needs NO explicit coordinates (atom i = `unravel_index(i, cshape)`), so `crd_int`/`C`/`coord_int` are None and block whitening uses block ids of the shared lattice (`frame_lattice`, shape (N,)) — never per-snapshot coord arrays.
- `dataset/wavecyclone.py` `WaveCycloneDataset` mirrors `CycloneDataset` structure: `path` + `trajectories` spec + backend, sorted conditions (itg/dg aliases), parallel metadata reads, frozen `WaveCycloneSample` (coords, coords_int, values, conditioning, flux, avg_flux, timestep, file/timestep_index, itg/dg/s_hat/q) + `collate`, plus pooled arrays `.X/.C/.P` for the runners. **Whitening is an input flag: `whiten=None` (raw, default) | `"global"` (pooled mu/sd) | `"block"` (per-wavelet-level-block diagonal whitening, exactly invertible, preserves quadratic flux)**; `nrm["whiten"]` records the mode ("none"/"global"/"block"), de-whiten via `_block_ids` for block. Legacy kwargs (data/params/data_files/data_dir) still work. No "tokens" naming in the dataloader (position–amplitude pairs).
- Linear-field conditioning (latent diffusion): `dataset/lincyclone.py` `LinearCondCycloneDataset` serves each trajectory's linear eigenmode field on `CycloneSample.linear` — ONE array per trajectory in a shared cache (`get_linear(fid)`; never copied per sample). **Spectral by default** (`linear_to_real: false`): the conditioning encoder never reconstructs, so the kx/ky inversion is skipped and it eats the semispectral `(2, vpar, mu, s, kx, ky)` field directly — 2 channels, and `linear_separate_zf` is REJECTED there (zf-vs-rest is a real-space split; ky=0 IS the zonal mode, and it is identically 0 in a linear run). Fields live as `<traj>/data/linear_k.bin` (fp32, local NVMe, written by `preprocess --mode=linear --materialize --space raw`); metadata carries the path plus reduced second moments (`linear_rms`, `linear_rms_cky` (2,nky), `linear_rms_ckxky` (2,nkx,nky)) from `--stats`. Preload of 240 fields: **3.9 s** from local bins vs ~2-3 min from raw FDS + ifft.
- Linear-field normalization: `linear_normalize: cky` divides by ONE global (2,nky) RMS profile pooled over the whole training split (`sqrt(mean_i rms_i^2)`); the val split INHERITS the training profile (the runner injects it — building one from 3 val trajectories would normalize val differently). Per-trajectory division is a separate opt-in (`linear_rescale_per_traj`, default off): the FDS RMS spans 28.6x across trajectories but 5th-75th percentile all sit at 0.010-0.013 with a ~10x tail above the 95th, so it is mostly conventional. **Never divide by a per-trajectory ky profile** — the eigenmode's ky spectrum is the conditioning signal (after the global profile, per-ky RMS is flat ~1 but still varies 8-28% across trajectories).
- `diffusion/lincond_dit.py`: `LinearFieldEncoder` (patch embed → Swin stages w/ PatchMerge → max pool over the grid → code) + `LinearCondDiT` (code concatenated into the DiT modulation; `__call__` takes the raw field for training or a precomputed `encode_cond` code for sampling). `n_cond=0` — the scalar (itg,dg,s_hat,q) path is NOT built and the runner asserts it; the 4 scalars only verify the latent cache's fid ordering and go to logs.
- Throughput levers (measured on one B300, AE_noCond latents, bs 256 / cond_group_size 16): fields AND latents device-resident (`linear_device_cache`, `latents_device_cache`) — a per-step host gather cost ~1 ms/sample and 117 ms/step of field copies, pinning util at ~1/3; `cond_group_size=g` draws batch/g trajectories x g timesteps so the encoder runs batch/g times per step (the code is computed once per group and repeated — exact, since the field is fixed and the encoder deterministic); `minibatch_ot` uses the gemm identity for its cost matrix (the explicit `(B,B,D)` difference is 19 GB at bs 256). bs 16 → 568 samples/s, bs 64 → 697, bs 256 → 2660 (54% util).
- Run: `python main.py workflow=diffusion_lincond dataset=cyclone_lincond_full model=diff/lincond_dit training=diffusion_lincond logging=wandb ae_checkpoint=<AE>/best.pth`. `latents_cache_train` reuses the torch DiT baseline's own 20.8 GB latents pickle (verified cos 1.0000 vs a JAX encode once the legacy swin residual is on — PARITY.md); the loader verifies and auto-remaps its trajectory permutation.
- Runners: `gyrowave/runner.py` (default FM), `runner_fixed.py` (A: values on fixed support), `runner_coordgen.py` (B: coord+value), `runner_wavedit.py`. `python main.py workflow=gyrowave ...`; dataset config `configs/dataset/gyrowave.yaml` (path + whiten flag).
- FM variants and their known failure modes (single-traj degenerate; flux is phase-sensitive, needs flux-aware objective) — see `/local00/bioinf/galletti/gyrowave_dwt_wip/wavelet_generative_deepresearch.md`.
- dwt20 dataset (20 param-diverse trajs, semispectral, CR400): `/local00/bioinf/galletti/gyrowave_dwt20/`; generate with `gyrowave_dwt_wip/launch_dwt20_pool.sh` (8-GPU self-balancing pool), verify with `gyrowave_dwt_wip/verify_dwt20.py`.

## Gotchas learned the hard way
- fp32 `np.cumsum` STAGNATES over ~10M elements (energy-capture curves must be fp64).
- jax.sparse buys nothing on the gyrowave recon path: the coefficient scatter (`.at[idx].add`) is only ~6% of recon time and BCOO matches it 1.0×, while ~94% is the dense per-axis synthesis (matmuls by nature). Keep handrolled scatter + dense synthesis; use pad+mask for ragged sets (static shapes for jit).
- `fftshift` vs `ifftshift` differ for ODD n; composition `ifftshift∘fftshift = id` for odd n (n=85 kx convention relies on it).
- `fastops.set_trajectory` (via PT.run/set_trajectory) MUST run before building TrajOps (geometry is per-trajectory); `_KS` K-listing cache is keyed by path — clear with `fastops._KS.clear()`.
- `jax.scipy.special.bessel_jn` inaccurate for |arg|>~40 — geometry uses scipy.special fp64 host precompute.
- DWT libraries: jaxwt ARCHIVED (Jan 2026); ptwt (torch, maintained) does NOT support `periodization` mode and is 12–37× slower than our matrix DWT on this workload; jaxwavelets (handley-lab) is immature. **We use our own pywt-built dense matrices as JAX tensordots** (`fastops._db4_axis_mats`, S@W=I asserted, differentiable, ~1–3 ms for the full 5-axis transform vs ~2.4 s pywt CPU).
- Bash: `cd X && cmd &` backgrounds the `cd` too (later relative paths break) — use absolute paths or `workdir`.
